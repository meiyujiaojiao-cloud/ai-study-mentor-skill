# V0.3 Phase 3：最小复习与延迟复测

只检查一个已保存知识点。复习是可选的，不自动提醒、不建立计划、画像或方法推荐模块。规则参数是实验设定，不是已验证遗忘模型。

## 日期与入口

已有明确写入授权且已有真实作答证据时，可在首次保存后调用存储工具的 review-schedule，建议次日复习。此调用同样需要 --confirmed 和最新 --expected-revision；失败须说明日期未保存。没有作答证据时不安排复习。

resume 会返回 review.due、delayed_eligible 与 due_date。到期时展示简短摘要和“先复习 / 继续学习 / 更换目标”，等待选择；未到期仍允许用户主动复习。用户选继续就恢复原位置，不强迫复习。跳过调用 review-skip 或直接停止，不改变原状态、证据或日期，不自动推迟。

日期是否到期按当前用户当地日期判断。延迟资格要求距最近一次实际作答至少24小时；新会话、日期到期或换题本身都不能证明已延迟。未满足时称提前/普通复习，证据为 related，不能标 delayed_passed。记录时间来自真实时钟；不能修改历史时间制造跨日。

## 新题与证据

先检查已有题目和未完成题。用户选择复习时，生成同一知识点、不同数据或情境的新题；代码题更换代码中的数据或访问位置。不复用旧题、旧答案或仅换措辞，不在出题时给出答案。未完成旧题仍可在“继续学习”时恢复；选复习则使用新题，只有确认保存新状态后才更新暂停位置。

等待实际回答。给过提示即标 hinted，完整答案已展示则标 explained，不能重新称 independent。记录 task_summary 必须完整包含题目数据/代码；不要用“复习题”代替。工具只排除规范化文本完全重复，语义上是否相关和不同仍须按规则检查。

新会话只恢复不等于授权写入；用户确认本次必要复测摘要保存到指定文件后，调用：

python -X utf8 scripts/learning_store.py review-result --path <授权路径> --expected-revision <最新值> --confirmed

标准输入是只有 task_summary、response_summary、reasoning_summary、correctness、assistance 的 JSON 对象。时间、related/delayed、状态与复习日期由工具计算，不由模型填入。工具拒绝重复新题、不合时序记录和并发覆盖。原有证据只追加，不能删除。

- 独立正确且理由成立：延迟资格满足时 delayed_passed，否则 immediate_passed；仅本知识点有新证据，不是全主题掌握。下一步让用户选择继续或复习。
- 提示/讲解后正确、理由不足或无法判断：needs_review，保留提示与证据边界；不能称独立掌握。
- 部分正确或错误：needs_review；读取并调用 [V0.2 错因诊断](错因诊断.md)，先判断证据，原因未知时问一个诊断问题。保留历史正确证据，后续再给不同相关题，不凭一次错误贴能力标签。
- 跳过：不提交 review-result，不添加虚构作答，不改变知识验证状态。

延迟独立通过后建议3天后再检查；其他实际复测结果建议次日检查。建议不是强制任务；日期只在用户主动恢复时检查，无后台工作。保存失败时明确本次未保存，不拿对话状态冒充文件状态。

## 工具接口与测试边界

review-status --path 只读取当前资格和日期；review-schedule --path --expected-revision --confirmed 保存初始日期；review-skip --path 不写入。

--test-now 是明确标注的模拟时钟，仅在测试用户明确请求时使用，并在报告说明“模拟时间”。正常用户学习禁止使用它伪造延迟证据。模型仍负责答案与理由的语义判断，工具不能证明真人理解、题目相关性或实际学习增益。
