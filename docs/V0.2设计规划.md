# V0.2 错因诊断方案（开发评审，未发布）

本轮唯一核心是错因诊断与针对性策略选择，取代此前好奇心/知识点结构的宽范围草案；后者延期，不在本轮实现。

## 顺序

先冻结12个虚构案例和五维评分，再运行普通Codex与冻结v0.1.3基线；只看8个开发案例。新增简短错因参考规则，区分观察、暂定假设与未知；必要时问一个诊断问题，针对偏差教学，换一道题复测，随解释更新。随后运行V0.2，最后揭开4个留出案例并按同一标准比较三组全部结果。

## 修改范围

SKILL.md、references/教学流程.md、新增references/错因诊断.md；README.md与README.en.md标明评审状态和已公开稳定版。新增tests/V0.2案例.json、tests/V0.2评分标准.md、tests/运行对照测试.py、tests/V0.2对照结果.json、tests/V0.2对比报告.md；必要时更新tests/验证文件.py以检查新资料。安装方式与原有中英文及A–E规则保持兼容。

## 设计约束

分类描述本题偏差，不评价学习者永久能力；不确定就澄清，不一次问长问卷。不向用户展示内部评分表，不在SKILL中写基准案例答案。数值正确但缺理由维持未验证；复测一次答对仅本题通过。用户可跳过、求解释或换目标。参考文件仍可被未来独立产品复用，但不新增数据库/API/记忆结构。

## 证据与验收

评分与明显改善门槛见 [评分标准](../tests/V0.2评分标准.md)，案例见 [固定案例](../tests/V0.2案例.json)。单次模型模拟结果不是学习者实测；若没有达到门槛如实报告，不宣称优于普通模型。

保持v0.1.3标签及线上main不变，使用独立评审工作区与codex分支；不发布V0.2 Release。当前安装仍指向原工作区，不自动替换安装。排除外部教材、长期记忆、数据库、网站、自动计划、多Agent架构与额外付费。
