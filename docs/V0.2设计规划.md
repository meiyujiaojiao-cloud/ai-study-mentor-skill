# V0.2 设计规划（未实现，待验收）

## 目标与范围
让学习从一个用户真正好奇的问题开始，用短讲解、具体例子和可检验的小目标帮助理解。
复用 V0.1.2 的目标采集、证据反馈与未验证状态；本文件不修改 SKILL.md 或当前教学流程。

## 拟议教学过程
1. 已有好奇心问题就直接使用；只有主题时，问“这个主题里，你最想弄明白什么？”可给最多两个切入例子，允许用户自己提问。不能强迫用户先回答新问卷。
2. 用问题确定当前小目标，仅补问缺失的基础和用途；用户已有明确学习目标时不让好奇心提问打断任务。
3. 先讲一个核心概念，配一个具体例子。默认约100–200字，可按用户基础调整；详细推导只在用户要求、存在关键误解或解决问题需要时展开。
4. 提出一个能检查理解的问题，等待真实回答；允许提示、跳过或结束。
5. 根据错误调整解释或前置知识，再用不同题验证；即使答对，也只给与证据匹配的结论。
6. 给一个下一步选择，不自动连续展开新内容。

## 根据错误调整教学
| 观察 | 拟议调整 | 验证 |
| --- | --- | --- |
| 概念混淆 | 对比具体例子和反例，指出第一个偏差 | 同概念换情境题 |
| 算术或步骤错误 | 保留正确概念，只拆出错误步骤 | 不同数字的小题 |
| 基础不足或听不懂 | 降低术语密度，换生活例子，回到必要前置知识 | 更小的单步检查 |
| 答案对但理由错/缺失 | 澄清理由，不能只按数值判理解 | 简短解释或迁移题 |
| 求提示、索要答案、跳过 | 尊重选择，记录辅助或未验证 | 以后自愿独立作答，不能提前记掌握 |

不依据一次错误给用户贴能力标签；不确定错误原因时先澄清。重复错误则缩小目标，不循环重复同一段话。

## 课程内问题与跨学科探索
课程相关问题：围绕当前知识点回答，必要时补一个前置概念，再由用户决定是否回到练习。
偶尔跨学科问题：先合理回应；说明与当前主题的联系（若有），再询问继续探索还是回原任务。
没有真实联系就直接说明，不能硬凑。偏题不会自动扩大课程、清空进度或增加待办。
用户明确换话题时保留原任务未验证状态；新主题另起知识点，不能继承原题成绩。
涉及需要最新证据的事实，按宿主环境可用能力核实，并区分不确定内容；不为探索自动申请付费服务。

## 未来知识记忆库可复用的结构
以下只是设计字段，不是已实现的数据库、API 或自动保存格式。先在对话摘要中使用，不新增存储依赖。

| 字段 | 用途 |
| --- | --- |
| concept_id / title | 稳定知识点标识与名称，避免同名主题混淆 |
| guiding_question / objective | 用户的好奇心问题与当前可检验目标 |
| prerequisites | 必要前置知识点标识 |
| key_idea / example | 核心解释与具体例子 |
| related_concepts | 相关知识点及课程内/跨学科关系，未知则留空 |
| evidence | 实际题目、回答、理由、是否使用帮助、反馈 |
| understanding / next_step | 复用 unverified、needs_practice、item_passed 与下一步 |
| source | 可选来源及不确定性，不保存教材原件或隐私 |

示例（虚构，仅设计）：
- concept_id：math.percent.discount
- guiding_question：为什么七折不是减去70%？
- prerequisites：math.decimal.multiply
- objective：区分支付比例与优惠比例并计算单次折扣。
- understanding：unverified；尚无独立作答证据。
同一知识点可有多条证据；关联关系不是掌握证据。用户未授权保存时不写文件，跨会话不能声称已恢复。
实际落盘、版本迁移、用户隔离和检索均留给后续单独设计，不在 V0.2 默认实现。

## 拟议验收用例（尚未执行）
- 只给主题：引出一个好奇心问题，不生成长课程；已给具体问题时不重复采集。
- 默认讲解简短且有具体例子；用户说“深入一点”后才按需求扩展。
- 同一知识点分别给概念错、算术错、基础不足，反馈方法应有差异。
- 正确答案但错误理由不得记通过；跳过与得到完整答案保持未独立验证。
- 从课程题转入跨学科问题，再返回时恢复原题与真实证据，不自动扩课。
- 知识点摘要区分问题、解释、关联和证据，不凭阅读记掌握，不声称已存入记忆库。
- 用户说“今天到此为止”立即停止，仅给可选摘要，没有强制提醒或自动推送。
实现时须保留 V0.1.2 A–E 回归检查；本轮没有运行或宣称上述新用例通过。

## 明确不做
无限内容流、自动连续推荐、强制提醒、网站、三模式完整框架、教材解析、向量数据库、自动持久化或付费 API 集成。
实现顺序建议：先修改小范围教学规则与示例，再执行真实多轮和回归测试；知识点摘要作为最后一项，避免先搭建记忆库。
